Structured Data // Operating Role

Schema is useful when it makes real relationships explicit.

Structured data is not a substitute for content, architecture, or technical health. Its job is narrower: represent eligible information in a machine-readable format that matches the page and helps search systems interpret entities and relationships more precisely.

01 // ENTITY

What does this page represent?

The first decision is the real entity or content type: organization, local business, product, service, article, breadcrumb, FAQ when eligible, or another supported type.

02 // EVIDENCE

Does the page visibly support the markup?

Properties should be grounded in content users can access. Schema should not claim reviews, offers, locations, services, or attributes the page does not actually present.

03 // RELATIONSHIP

How does this entity connect to the rest of the site?

Organization, location, product, service, brand, webpage, and breadcrumb relationships can help create a clearer model when they are implemented consistently.

04 // VALIDATION

Is the implementation technically valid and still eligible?

Syntax, required and recommended properties, platform output, duplicate markup, and current search-engine eligibility all need verification after implementation.

Raptor uses structured data as part of the broader search system. The exact schema depends on the business, the page, the visible content, platform capabilities, and what search engines currently support.

Structured Data // Quality Standard

Schema should clarify the site, not decorate it.

Raptor treats structured data as technical evidence. If a property is unsupported, misleading, duplicated, or disconnected from visible content, adding more markup does not make the implementation better.

×

Not keyword stuffing in JSON-LD. Markup is not a hidden content field.

×

Not unsupported claims. Properties need visible, accurate evidence.

×

Not every schema type everywhere. Use only what fits the page and supported use case.

×

Not install-and-forget. Template and business changes can make valid markup wrong later.
